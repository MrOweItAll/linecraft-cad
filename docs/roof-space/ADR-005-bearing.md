# ADR-005: bounded different bearing heights

> **Historical milestone reference.** This document records its original R0–R6 implementation scope and evidence. It is retained for design history; its status, next-step and test statements are not current v1.36 qualification claims. See [the historical-reference index](../HISTORICAL-REFERENCE.md) and [current release notes](../RELEASE-1.36-BETA.md).

R5 extends the existing original rectilinear finite-front solver. A declared eave height delays activation; every active front retains the same selected pitch. With minimum height e0 and pitch p, edge i activates at (ei-e0)/p and advances by max(0,t-delay). Stationary boundary intervals may sweep vertical interfaces before activation. Explicit gable ends remain stationary. This is an original bounded implementation with no new geometry dependency.

The solver includes all activation and coordinate-contact heights, batches simultaneous contacts, reconstructs finite occupied fronts between events, and merges legitimate swept patches. It does not apply unrestricted global plane envelopes across a concave footprint. Unresolved finite-endpoint provenance, consumed supports, open coverage or failed runoff produce an explicit failure/unsupported result with no partial accepted skin. A source edge consumed before its declared activation is infeasible. This does not construct arbitrary stepped multi-roof alternatives.

Schema 5 adds roofGroup.bearingAssignments, an array of geometric edgeKey/elevation overrides. Missing assignments retain default bearing elevation or matched source-wall elevations. Schemas 1–4 migrate in memory without changing historical files. Source-only persistence never saves roof vertices, steps or other caches. Ceiling elevation, bearing elevation, heel offset and geometric eave elevation remain separate. Eave overhang drops a sloping front by pitch times overhang; rake extension does not. A single explicit common eave cannot override unequal bearings.

Matched source-wall elevations govern their boundary edge. Conflicting overrides, inconsistent collinear wall heights on one merged edge, and variable-height unmatched/interior supports require a decision. Geometric correspondence does not verify framing or a load path. Explicit boundary overrides do not silently edit walls. Bearing changes and their regeneration use the existing grouped transaction; impossible changes leave the accepted source and Undo history intact. A pure preview calls the same normalized support resolution in isolation.

Separate zero-thickness step and gable-closure meshes retain roof ownership and ordinary-edit guards. Sloping skin is the ceiling-analysis cap; vertical interfaces do not acquire roof area or automatic structural status. Roof-skin area, closure areas, modeled reservations and actual geometry remain available; framing lumber/connectors remain unknown. Both owner-specified truss surcharges remain exactly zero.

Analytical gate: 20 ft opposing span at 4:12, low/high bearings 10/12 ft gives ridge at 13 ft from the low edge and elevation 14 ft 4 in. Returning both bearings to 10 ft reproduces the existing solver's baseline geometry. HIP corner checks include separately generated vertical north-edge interfaces. Rotation/translation, units, support conflicts, source round-trip, grouped history and independent physical PDF checks are required.

The existing application, camera/picking, native units, layers, layouts and vector PDF path remain in use. This milestone does not provide engineered framing, arbitrary split wall-bearing chains, courtyard holes, variable pitches, composed overlapping roof groups, hidden-line PDF or shaded PDF.
