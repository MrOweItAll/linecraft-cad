# Synthetic structural file-service coverage

The candidate fast profile recovers 37 reviewed original checks: nine V1, thirteen
V2 and fifteen V3. They run real main IPC handlers, core validators and bounded JSON
reads/atomic writes, with fake Electron windows, transport and dialog selections.
The V3 input is the byte-preserved generic mixed-pitch sample. No client drawing,
renderer, native dialog, installed application or external engine is opened.

Public adapters preserve every original assertion. They normalize line endings,
register sequential Node tests with propagated failures, restore the module loader
in finally, reject Electron and extra application arguments before loading main,
and use exclusive new output folders. Reports stay in the owned QA run folder
(or source work directory for a standalone invocation), outside public test inputs.
The generator CLI is never executed. The sample and all four suites are gate inputs.

One additional host case supplies a literal V1 result: area100 SF per comparison,
pitches6/8, R1=.8, R2=1, L0=20 and Lr=16 PSF. Only source/region/face identities bind
to the request. The joined main component has four exposed faces, two per pitch:
the central wing exceeds the main ridge and splits each main plane left/right.
No sum or load-path interpretation is made. Altered version/kind, export hash,
document hash, architecture hash and region identity each reject while source and
request bytes remain unchanged.

Four independent callback-contract cases verify the literal V1/V2/V3 mode table,
exact export/load/import order, selected validated return objects, six mismatched
result-version paths and rejection before further chooser/read/result callbacks.
Their opaque sentinel objects are not real roof schemas. Restored host checks
separately use production schemas and real owned files.

The first focused run passed41 of42 checks. The new V1 case incorrectly expected
two faces; independent fixture-plane analysis established four exposed pieces.
The correction retains area/factor/load literals and adds one result row per bound
face. The failed receipt is retained. No product runtime repair was indicated.

These checks qualify synthetic mocked-host/file-service contracts only. They do
not establish actual native UI/installed/upgrade acceptance, external-engine
execution authenticity, structural standards/capacity/load path, DWG-consumer or
client fidelity, production relay or daily-use readiness. Existing descriptor
runtime privacy, signing and packaging/release requirements remain separate.
